## 结论和适用范围

当前可进入同一高度平地走廊的分段验证，不能据此认定整层长距离或连续楼梯自主导航已可用。用户已确认路线有连续台阶。楼梯段暂不纳入自动路线：在楼梯前结束任务，由人工接管通过，在下一平台重新确认地图、定位和朝向后另起任务。不同高度的平台优先分别建图与定位。

本轮没有发送运动指令。修复现已同步到板端统一目录，并在板端通过 42 项交互/路线测试及 2 项定位策略测试；语法检查通过。原文件备份于板端 `board/backups/audit-20261016-135321/before.tar.gz`。后续系统运行与验收在板端完成，本机只编辑代码、SSH 操作及显示 RViz。

用户确认现有地图范围足够，本阶段不以扩大地图为任务；下述范围信息仅作为能力边界记录。

部署后板端60秒静止共载检查通过（融合会话 `board-20261016-135436-2841`）：输出5.026 Hz，融合延迟P95 0.181秒，导航位姿年龄P95 0.281秒，点云年龄P95 0.377秒、最大0.457秒，最高CPU温度60.7℃。证据位于板端 `board/evidence/audit-20261016-board-60s.json`。此轮未激活旧图定位，不能算旧图定位修复的实时验收，更不能算楼梯运动验收；地图与目标保留，菜单状态为已选地图、待重定位。

## 连续楼梯后续方案与接口证据

用户说明上楼使用 App 越障模式。该说明用于确定上楼候选模式，尚未证明 SDK 能切换，也没有提供下楼实测结果。

2026-10-16重新读取[宇树 Go2W 高层服务文档](https://support.unitree.com/home/zh/Go2-W_developer/sports_services)，页面更新日期为2026-04-08。文档列出 SwitchGait(1) 为爬楼梯/地形行走模式，但明确注明“此接口暂不提供”。[官方 Python Go2W 示例](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/example/go2w/high_level/go2w_sport_client.py)仍调用 SwitchGait，而当前公开 SportClient 和板端安装的 SDK 头文件均未提供此方法，不能直接按示例执行。不得把其他机器人型号接口或控制器名称当作 Go2W 步态枚举。

板端只读探测返回控制器身份 `ai-w`、原始 mode=1、gait_type=0、零速度，收到31条状态消息。原始状态字段与 App 越障状态之间的映射尚未实测；这不是支持模式清单，也不是切换成功证据。

拟采用板载状态机：平地到入口 → 停稳并对齐楼梯轴线 → 确认越障模式 → 楼梯段专用跟踪 → 确认到达平台 → 校验平台定位 → 恢复平地导航。此处是待实现方案，不是当前可执行功能。

优先复用官方已具备的底层越障控制能力，不重写腿部控制。仍需补齐：

1. 确认本机固件支持的切换 API 与回读；公开接口未提供时，先使用 App 手动切换并做只读状态对照，不构造未知 RPC。
2. 采集人工遥控上下楼的板端数据，分别验证融合在俯仰/高度变化中的稳定性，以及台阶边缘、扶手与平台的可观测性。
3. 楼梯段使用有高度信息的路线/地形判断；不能把楼梯障碍清空后继续让平地 MPPI 直接行驶，也不能只按行驶时间判定到达平台。
4. 为上下楼分别定义进入条件、速度及姿态限制、落脚/落差检查和异常接管策略；目前尚无足够数据确定这些参数。
5. 支持平台地图关联、楼层/高度确认和定位验证；确认完成后才进入下一平地任务。

## 已验证基线

- 板端 MAXN，FAST-LIVO2 视觉输入 5 Hz，640×360，4 个 OpenMP 线程；Nav2/MPPI 同机运行。
- 上一轮 60 秒全栈静止采样：融合输出约 4.97 Hz，融合延迟 P95 0.226 秒，位姿年龄 P95 0.329 秒，点云年龄 P95 0.382 秒、最大 0.442 秒。
- 10 Hz 曾在较长实时运行中出现积压，因此不能用短回放成功证明持续实时可用。
- 当前采用 0.2 m/s 基线，不是 0.8 m/s 大厅参数。5 Hz 是视觉/融合配置，不是 MPPI 控制频率；控制器为 20 Hz，但输入位姿不会因此变为 20 Hz 的独立观测。
- 这些结果证明静止时的数据链路可工作，没有证明长走廊运动、连续台阶或长期热负载下的精度。之前桌面端约 7 cm 的现场结果不能当成板端长距离精度保证。

## 实际闭环和任务流程

传感器 → FAST-LIVO2 融合位姿/点云 → 旧图定位变换 → Nav2 全局规划与 MPPI → 速度平滑及碰撞/新鲜度保护 → SportClient 高层速度指令。导航依据实时融合位置闭环，不以速度乘时间计算到达。

新建图后保存二维地图和定位点云；恢复旧图需要匹配成功并核对位置与朝向。保存导航地图不等于停止融合，持续定位仍需要传感器输入，融合自身也仍有内部地图更新。

多途经点绑定地图、定位会话和路线指纹；预演有效期 60 秒。每段运动前重新规划，达到位置/朝向容差并确认停稳后才继续；任一段失败则中止剩余路线。当前默认停留 2 秒后自动进入下一点，**这不是等待人工确认的检查点**。不要将楼梯前后两点放入同一条自动执行路线。

## 本轮已部署修复

1. 旧图定位的停稳检查补上横向速度，并要求新鲜里程计，避免轮足转向伴随侧移时错误执行静止校正。
2. 旧图校验要求新鲜且时间戳递增的点云，避免重复使用缓存点云刷新健康状态。
3. 多点任务只接受本段新产生或更新的执行结果，并核对完整目标指纹，防止读取上次成功记录后错误进入下一点。

相关文件：`navigation/mppi/localization_policy.py`、`navigation/mppi/localization.py`、`demo/mission.py`。新增模块已加入迁移包清单。回归覆盖停稳/新鲜度和旧结果误用；部署后还需静止全栈验证，不能仅凭单元测试认定可运动。

## 长距离尚未解决的限制

| 项目 | 当前行为与影响 | 后续工作 |
|---|---|---|
| 连续楼梯 | 二维代价地图不提供完整三维可通行性、落差检测或楼梯控制 | 独立楼梯能力验证与分层任务设计；当前人工接管 |
| 到点切模式 | 参数和校验接口存在，但 Go2WModeAdapter 尚无已验证的模式调用与回读；会拒绝执行 | 先确认固件接口并验证反馈，不能猜测模式值 |
| 二维范围 | 新建图配置固定 60×60 m、原点 (-30,-30)；不是任意方向均可走 60 m；旧图范围以自身元数据为准 | 根据实测路线确定范围，评估分图与内存，不能仅放大参数 |
| 点云保存 | 每批点云重新合并、去重整张图，达到 200 万体素会失败 | 增量体素存储、分块保存及资源上限测试 |
| 旧图匹配 | 周期性对整张保存点云做 ICP，可能阻塞定位节点 | 局部子图、异步匹配与超时保护 |
| 累计漂移 | 运动期间校验旧图但冻结校正；超过阈值会停车 | 检验每段末端漂移，设计有界连续校正或重定位流程 |
| 多点停留 | 默认 2 秒后自动继续，未保证全局校正已收敛 | 增加显式定位收敛条件及必要的人工检查点 |
| 障碍恢复 | 当前行为树有重规划，但没有完整等待/重试恢复序列 | 先验证障碍停车，再设计有界恢复，禁止盲目重试 |

其中大地图性能、连续校正、楼梯能力本轮没有实现，不应作为已经修复的功能宣传。

## 建议下一轮实验

1. 修复已同步并保留回退备份；无运动共载检查与旧图重定位分别验收。重启后不得沿用上一会话的定位变换或预演。
2. 选择台阶之间的平地走廊，包含完整往返路线建图；检查地图边界、走廊障碍和定位箭头。楼梯口不得被当作普通可行驶区域。
3. 以 0.2 m/s 开始，初期每段约 5–10 m，在转角和楼梯前设置任务终点；此距离只是实验分段建议，不是已验证能力指标。
4. 连续记录 15–30 分钟运行数据：传感器/位姿年龄、处理耗时、CPU 温度、内存、地图规模、定位匹配质量和所有停车原因。数据积压先解决，不能通过放宽过期保护掩盖。
5. 在同一固定机身参考点测量每段位置与朝向误差，另测回到起点的闭合误差。SLAM 自报误差不能替代卷尺/标记的实际误差。
6. 平地测试通过后再讨论提速；楼梯通过与跨平台定位作为独立实验，不与首次长走廊测试合并。
