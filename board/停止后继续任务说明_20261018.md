# 停止后继续任务（2026-10-18）

网页地址：http://192.168.123.18:8088/ 。更新后刷新网页，必要时重新输入原访问码。

1. 导航中按“停止导航”或触发数据/定位/障碍保护后，等待实机停稳。任务显示“已停止，进度保留”。
2. 查看“已完成 x/y；继续顺序”，处理障碍、线缆及输入异常。定位与输入恢复后，点击“预演剩余路线”；这一步不会运动。
3. 预演通过且仍有效（60秒）时，点击“继续未完成任务”，阅读剩余点顺序并确认，之后有5秒倒计时。
4. 从第一个未确认成功的点重新规划和执行；只有位置、朝向、停车、停稳及要求的到点模式切换全部通过，才记为完成并前往下一点。不会仅凭“接近目标”跳点。

“从头重新执行”表示从第一个点重新开始，与“继续未完成任务”不同。单点任务可以重新预演并导航同一个目标，不使用多点进度恢复。

重复点按序号处理：A→B→A完成前两个后，继续的是最后的A。人工接管点必须为末点，结束后不能自动继续越过楼梯。

地图、路线顺序、目标位置/朝向/到点动作或融合会话改变后，旧进度不可直接继续。当前功能用于本次定位会话内的停止/保护恢复；机器人重启或重新建图后需重新定位并建立任务。预演后若机器狗移动超过5cm或约5.7°，也必须重新预演。

网页连接中断、定位异常、传感器过期和碰撞保护仍生效。恢复数据不会自动恢复运动；继续必须由操作者明确点击。继续过程中再失败，会保留已完成数量。

命令行入口（板端项目目录）：
```
python3 demo/console.py route-resume-preview
python3 demo/console.py route-resume
```
交互菜单：19=预演剩余路线，20=继续未完成任务。第二条命令/菜单20会真实运动。

## 本次修复补充

- “预演剩余路线”不发送运动指令，允许在瞬时输入异常时短暂等待恢复；持续异常仍会报出具体原因。
- “继续未完成任务”仍须定位、输入、预演全部有效；不会因数据恢复而自动运动。
- 从头重新执行时，如果存在停止任务，网页明确提示将从第一个点重新开始，服务端核对当前任务标识。旧进度另存历史文件。
- 点云过滤提前到单独线程，待处理槽只保留最新帧；仍按原始时间戳等待融合TF覆盖。使用相同5厘米体素、相同保留点规则，优化排序和ROS字节数组赋值。
- 输入状态更新从5Hz改为20Hz，并在发布新点云后立即更新。未提高运动数据过期阈值、未修改速度/到点容差。
- 删除已发布TF之后额外固定等待25毫秒的步骤；仅放行时间戳已被融合TF覆盖的点云，跨进程接收顺序交给ROS MessageFilter等待实际变换到达，不更改点云时间戳。
