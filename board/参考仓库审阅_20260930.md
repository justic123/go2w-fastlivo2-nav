# TONYHEGUAGUA/FAST_LIVO2 参考审阅

来源：https://github.com/TONYHEGUAGUA/FAST_LIVO2

审阅提交：`47bdc0fd2039aaa48179e90966c5ff8d869a99d1`。
只读取和比较源码，没有运行该仓库脚本或将其配置部署到机器人。

## 结论

可以作为 NX 上 MID360 + D415 的接入案例参考，未发现可直接移植的 CUDA/GPU 加速实现。
本次比对中，`src/vio.cpp` 和 `src/voxel_map.cpp` 与本项目固定依赖的对应文件 SHA-256 完全一致。
ARM 编译优化和 OpenMP 设置也是已有实现，因此不能把该仓库名称中的“NX 部署”理解为 GPU 优化。

## 与当前实机的差异

| 项目 | 参考仓库 | 当前 Go2W |
|---|---|---|
| 雷达 | MID360、Livox 数据接口 | XT16、点云与逐点时间适配 |
| IMU | `/livox/imu` | LowState 机身 IMU |
| 相机 | D415，1280×720 参数 | 原装广角相机，缩放至640×360 |
| 外参 | 该作者的传感器安装参数 | 当前 Go2W 的标定候选 |
| 图像时间偏移 | 0.1秒 | 0秒，曝光时间仍待标定 |
| GPU后端 | 未发现 | 本分支独立实现的CUDA对照原型 |

不复用其相机内参、外参、IMU噪声、图像偏移或点云格式处理。
参考仓库同样保留200000条订阅队列，关闭局部地图滑动，开启稠密点云与PCD/COLMAP保存；
未发现可验证“长时无积压”的专门基准或遥测结果。其IMU文件还添加了高频调试输出。
这些内容不能作为本次分钟级延迟问题已经解决的依据。

本分支只记录参考结论；没有复制其算法代码。原项目及本项目的第三方FAST-LIVO2补丁仍遵守原GPLv2许可。
